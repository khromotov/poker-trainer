# Poker Trainer

Два локальных тренажёра Texas Hold’em с интерфейсом для телефона: **«Префлоп дуэль»** и **«Тренажёр решений»**. [Открыть приложение](https://khromotov.github.io/poker-trainer/).

## Префлоп дуэль

Оцените equity двух конкретных рук, проверьте ответ расчётом Монте-Карло и переходите к следующей задаче. Equity — вероятность победы плюс половина вероятности ничьей. Проценты можно вводить с точкой или запятой: `40.5` и `40,5` равнозначны.

Режим Random выбирает реальные комбинации из колоды; типы стартовых рук встречаются с естественными частотами. Balanced и Mixed используют упрощённые категории для разнообразия задач. В настройках доступны режим и число симуляций, в статистике — история, ошибки и JSON экспорт/импорт. Монте-Карло не гарантирует фиксированную максимальную погрешность.

## Тренажёр решений

Нажмите «Получить раздачу»: приложение раздаст вам и ботам настоящие случайные карты из одной колоды. Боты сами играют до вашего хода. Выберите фолд, чек, колл, бет/рейз или олл-ин; поле ставки означает **полную ставку на текущей улице**, без анте. Для первой ставки на постфлопе доступны кнопки долей банка. Доплата и банки учитываются автоматически.

После вашего действия появляется учебная оценка с объяснением. Пока вы не нажали «Продолжить раздачу», показывается ситуация **до решения**: следующие карты и действия не раскрываются. Раздача продолжается через флоп, тёрн и ривер, либо заканчивается раньше после фолдов. На вскрытии автоматически учитываются лучшие пять карт, побочные банки и делёж. Затем доступны карты соперников, причины ходов ботов и разбор ваших решений. Выигрыш сам по себе не означает правильное решение, проигрыш — ошибку.

Настройки: от 2 до 10 игроков, по умолчанию 10; стартовый стек 30 000, блайнды 100/200 и BB ante 200. Можно изменить число игроков и стартовый стек, включить или выключить случайную глубину стеков. Новые настройки применяются со следующей раздачи. Каждая раздача самостоятельная: это не непрерывный турнир со сменой уровней и реэнтри.

В настройках можно выбрать стадию турнира. Глубины указаны **до блайндов и анте**:

| Стадия         | Случайная глубина                      | Без случайной глубины    |
| -------------- | -------------------------------------- | ------------------------ |
| Ранняя         | До 150 BB, ограничено стартовым стеком | Указанный стартовый стек |
| Середина       | 25–60 BB                               | 40 BB                    |
| Поздняя        | У вас 15–25 BB, соперники 10–40 BB     | 20 BB                    |
| Финальный стол | У вас 10–15 BB, соперники 8–30 BB      | 12 BB                    |

После ранней стадии реэнтри считается закрытым. Стартовый стек турнира остаётся в настройках ранней стадии; остальные пресеты задают текущие стеки в BB независимо от него. «Сохранить» меняет следующую раздачу. «Сохранить и начать новую раздачу» сразу создаёт ситуацию с выбранными настройками, заменяя незавершённую раздачу без записи в архив. Стадия текущей раздачи не меняется задним числом и сохраняется в истории и JSON; старые сохранения без стадии считаются ранними.

### Как устроена оценка

Это **авторская учебная модель, не GTO-солвер и не точный расчёт EV**. Стратегии и предполагаемые диапазоны заданы эвристическими правилами с учётом позиции, действий, ставок, структуры борда и стиля соперника. Оценка equity использует случайные гипотетические комбинации из этих диапазонов. Точный ICM, рейтинговые очки и рейк не рассчитываются. Погрешность выборки не измеряет ошибку стратегической модели.

На постфлопе против одного соперника без побочных банков сравниваются чек, колл, фолд, несколько размеров ставок и введённая вами **конкретная сумма**, а не только название действия. Модель рассматривает фолд, колл и одно ответное повышение на текущей улице, а для чека — возможную ставку соперника. Размер влияет на предполагаемый диапазон продолжения. Это позволяет оценивать защитную ставку с уязвимой готовой рукой: она может выбить оверкарты и лишить их возможности улучшиться. Соперник принимает решение только по своим гипотетическим картам и публичному борду; он не знает вашу руку и будущий результат.

После этой ограниченной ветки модель предполагает вскрытие без новых ставок. Она не решает будущие улицы и не доказывает оптимальность размера. Проверяется устойчивость к нескольким авторским вариантам реакции соперника; при близких или неустойчивых оценках ответ — «Неоднозначно». Мультипоты и другие неподдерживаемые постфлоп-ситуации также получают явную неопределённую оценку вместо уверенного вывода из одной силы комбинации. 55 на QQ3 не считается обязательной ставкой: значение имеют позиция, предыдущие действия, диапазон и размер. Общие принципы: [небольшие ставки на флопе в MTT](https://blog.gtowizard.com/flop-heuristics-ip-c-betting-in-mtts/), [реализация equity](https://blog.gtowizard.com/equity-realization/) и [выбор размеров ставок](https://blog.gtowizard.com/overchoice-making-sense-of-multiple-sizings/). Численные параметры приложения заданы нами; готовые стратегии источников не копировались.

Сохранённая пауза разбора может содержать оценку прежней версии. Кнопка «Пересчитать оценку» обновляет её по исходной публичной ситуации и выбранной сумме, без повторения хода и без доступа к открывшимся после него картам. Оценки остальных решений в архиве автоматически не переписываются.

Эффективные повышения больше двух банков после колла выходят за принятую границу достоверности реакций: их значение в модели вычисляется, но они не рекомендуются ботам и не получают уверенной оценки. Короткий эффективный олл-ин внутри этой границы поддерживается.

Стадия влияет и на действия ботов, и на разбор. Для дорогого продолжения против покрывающего стека добавляется явно заданная учебная осторожность к риску вылета; такая поправка не вычислена из выплат и **не является ICM**. Короткий стек сохраняет варианты открытия пушем и перепуша: риск вылета не превращается в правило «всегда фолд». В хедз-апе отдельная турнирная поправка не применяется. Источники для общих принципов: [GTO Wizard — ICM Basics](https://blog.gtowizard.com/icm-basics/) и [игра блайндов при ICM](https://blog.gtowizard.com/icm-and-blind-battles-the-small-blind/). Численные коэффициенты приложения — собственные учебные допущения; таблицы стратегий из этих источников не копировались. Для полноценного ICM нужны стеки и структура выплат, как в [HRC MTT Calculator](https://www.holdemresources.net/mttcalculator).

В префлоп-модели игроки, ещё не уравнявшие ставку, не считаются обязательными участниками будущего вскрытия: они могут сфолдить по авторской вероятности продолжения. Карты всех гипотетических игроков, включая сфолдивших, остаются удалены из колоды. Эта часть не решает дерево будущих ререйзов и не добавляет их предполагаемый выигрыш к текущей цене банка; при возможных ответах игроков позади разбор остаётся осторожным.

Каждый бот принимает решение по своим картам и публичной информации. Модуль оценки вашего действия получает отдельное публичное наблюдение: вашу руку, открытые карты, стеки и историю ставок. Реальные карты соперников, будущий борд и приватные объяснения ботов в него не передаются. Нет правила «готовый натс всегда чек/колл»; допустимость агрессии зависит от ситуации и явно заданной модели.

Режим ручного ведения стола с матрицей рекомендаций снят с главного меню. Его прежние локальные сохранения остаются нетронутыми.

## Данные и офлайн

Тренажёры работают локально, без API. История дуэлей хранится в IndexedDB `poker-trainer`, решения — в отдельной базе `poker-decisions`. Прежняя база стола `poker-table` не удаляется и не заменяется. Общая цветовая тема хранится в localStorage.

Текущая раздача сохраняется после каждого действия вместе с полной колодой, картами и паузой оценки, чтобы после перезагрузки продолжить тот же сценарий. Запись завершения и архива атомарная. Экспорт решений содержит **только завершённые раздачи**: их карты, действия и оценки. Импорт проверяет формат, добавляет отсутствующие архивы и не заменяет текущую тренировку. Данные сохраняются на конкретном устройстве; для переноса используйте JSON экспорт.

Первый запуск и загрузка обновления PWA требуют сети. После полной загрузки приложение и расчёты доступны офлайн. На iPhone откройте сайт в Safari → «Поделиться» → «На экран Домой». Проверка на физическом iPhone остаётся ручной: запуск в авиарежиме, расчёт в обоих тренажёрах, восстановление после закрытия, экспорт истории и обновление по уведомлению. Десктопная сборка не подтверждает эти проверки. Очистка данных браузера может удалить локальные сохранения.

## Разработка и публикация

Нужен Node.js 22 и npm:

```sh
npm ci
npm run dev
```

Проверки перед публикацией:

```sh
npm test
npm run typecheck
npm run build
```

Расчёты ботов и учебных оценок выполняются в Web Worker. Автоматические тесты проверяют комбинации, легальность ставок, сохранность фишек, побочные банки, переходы улиц, скрытие приватных данных, воспроизводимость раздач, границы учебной модели и независимое хранение истории.

GitHub Pages публикуется workflow [pages.yml](./.github/workflows/pages.yml) после push в `main`: тесты → проверка типов → сборка → публикация. В настройках репозитория выберите Pages → Source → GitHub Actions. При другом имени репозитория измените `base` в [vite.config.ts](./vite.config.ts). После успешной публикации примите предложенное приложением обновление.
